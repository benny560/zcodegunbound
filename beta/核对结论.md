# 老计算器 (Trico 3in1 Calculator) 反汇编核对结论

## 一、文件性质
3个文件都是 **VB6 原生编译**(native code,非p-code)的 Windows GUI 程序:
- `2.1.6.exe`(2007-10-02, 1.63MB)
- `2.2.2.exe`(2008-05-10, 1.93MB)
- `2.2.3.exe`(2008-07-09, 1.93MB, 内部名 020430Trico3in1Calculator)

公式已编译成 x86 机器码(2.2.3 含 22854 个 x87 浮点指令),无法一键还原 VB 源码。

## 二、核对结论(核心)

### ✅ 一致:角度计算的基础数学结构
从反编译提取出的核心函数(`FUN_00519520` 等 5 个,运算密度 163~165 次/函数)共用同一套常量:
| 常量 | 含义 |
|------|------|
| **57.29** (出现4次) | = 180/π ≈ 57.2958,**弧度转角度**(atan 结果转度数) |
| **10.2824** (3次) | 核心系数,疑似速度→圈数或时间→相位的换算 |
| **4.03** (2次) | 疑似某物理参数 |
| **7.1** / **1.72** / **5** / **2** | 待定物理系数 |
| **0.5** (大量除法) | 半程/平均运算 |

**结论**:老计算器用 `atan` 求角度后乘 `57.29`(180/π)转成度数 —— 这与现计算器的角度求解逻辑(`Math.atan(tanA)*180/PI`)**数学结构一致**。

### ✅ 一致:双物理模型
2.2.2/2.2.3 的 .text 段同时检测到:
- **g = 196**(GME 物理,3 处)= 9.8×20
- **g = 430**(Excel 物理,2 处)= Trico 专用重力
- **9.8**(2 处)= 原始重力加速度

**结论**:老计算器同时实现了 GME(196)和 Excel(430)两套物理模型 —— 与现计算器 `TRICO.gravity=430` + 全局 `Gravity=196` 的结构**完全对应**。核对 Trico 时应找老计算器里用 g=430 的分支。

### ⚠️ 差异:具体物理参数存储方式不同
现计算器的关键参数在老 exe 里**没以 IEEE754 浮点精确匹配**:
| 现计算器参数 | 值 | 在老exe中的情况 |
|------------|-----|----------------|
| PF(power factor) | 0.004332712 | 未找到(精确) |
| Trico mass | 0.23 | 未找到(精确) |
| ELEVATION_PIXELS | 516/13≈39.69 | 未找到 |
| DISTANCE_PIXELS | 40 | 未找到 |

**可能原因**:
1. 老计算器用了不同的参数值或表达方式(如 mass 存为整数再转换)
2. 这些值以内联在代码里的运算表达(非独立常量),或用了 Single 精度近似
3. 老计算器可能用不同的力度/距离归一化体系

### ⚠️ 版本演进
- **2.1.6**(2007):较旧,`57.29`×3, `7.1`×2,无 g=196/430 命中
- **2.2.2/2.2.3**(2008):引入双物理模型(g=196+430),`57.29`×2,多了 `2.5`(=sdParts/8 换算系数)

## 五、可行性与建议
**已验证可行的提取方式**:Ghidra 静态反汇编 + 常量字节搜索,成功提取了:
- 角度计算的数学结构(atan + 57.29 转度)
- 双物理模型(g=196 + g=430)
- 一批浮点系数

**局限**:VB6 native 反编译代码是底层指针操作(变量全是 local_xxx/undefined4),5个核心函数各 5~8 万行,**人工逐行还原完整公式成本极高**。

**如果要拿到完整公式**,最有效的后续路径:
1. **动态调试**(x64dbg/OllyDbg):在 `__vbaVarPow` 下断点,输入已知(距离/风/角度),看浮点栈寄存器的实际值流,直接验证公式。这比读反编译快 10 倍。
2. **黑盒采样拟合**:运行 exe,系统输入多组参数记录输出,用现成的拟合脚本(项目里已有)反推系数。
3. **精读单个核心函数**:锁定 `FUN_00519520`,追踪 `768.245`/`10.2824` 等关键常量的数据流。

## 六、总体核对结论
**老计算器与现计算器在物理模型架构上是一致的**(都基于 atan 求角度 + g=430/196 双模型),**核心数学结构可信**。但具体物理参数(PF/mass/距离归一化)的存储方式或数值可能有差异,直接逐数值核对会有出入,建议以"结构核对"而非"数值精确比对"为主要参考。
